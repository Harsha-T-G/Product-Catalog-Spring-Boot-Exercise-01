# Product Catalog Product Specification

**Status:** Approved — Week 6 (PostgreSQL persistence) implemented on branch `week6-exercise-6-docs-delivery`  
**Stack:** Java 21, Spring Boot 3.4.x, Maven, PostgreSQL 16, Flyway, Spring Data JPA, JUnit 5, Mockito, Testcontainers  
**Exercise source:** Week 5 fundamentals + Week 6 PostgreSQL exercises

## Assumptions

1. Base package is `com.codewalnut.productcatalog`; Maven coordinates are
   `com.codewalnut:product-catalog`.
2. Week 6 work extends the Week 5 REST API on branch checkpoints
   (`week6-exercise-1-postgresql-config` through `week6-exercise-6-docs-delivery`).
3. Products are persisted in **PostgreSQL**. Flyway owns schema; Hibernate
   `ddl-auto=validate` only. Spring Data JPA is the persistence boundary.
4. Lombok is used on DTOs and entities (`@Getter`/`@Setter` or `@Value`). Constructor injection only; no field `@Autowired`.
5. Controllers handle HTTP only. Business logic lives in the service layer.
6. REST boundaries use request/response DTOs; JPA entities are never returned
   directly.
7. Product id is a UUID generated by the application on create and never changes
   on update.
8. SKU comparison is case-insensitive for uniqueness checks (DB unique index on
   `LOWER(sku)` plus service pre-check).
9. Price uses `BigDecimal`, must be greater than zero, and must fit
   `NUMERIC(19,2)` (`@Digits(integer=17, fraction=2)`).
10. Inactive products (`active=false`) are stored and retrieved normally but
    excluded from low-stock queries.
11. Secrets and environment-specific overrides use environment variables (`.env`
    locally), not committed configuration files.
12. Java 21 is the release target.
13. API base path remains `/api/products` (no `/api/v1` in this exercise).
14. Optional `version` on update/stock requests enables optimistic-lock
    preconditions; omitting `version` allows last-write-wins on PUT.

## Objective

Build a Product Catalog REST API that demonstrates Spring Boot layered design,
validation, centralized error handling, type-safe configuration, PostgreSQL
persistence with Flyway migrations, paginated/filtered listing, stock adjustment,
optimistic locking, and Testcontainers-backed automated testing.

## Scope

### In scope

- REST API for product CRUD, paginated/filtered list, low-stock listing, stock PATCH
- PostgreSQL + Flyway schema + Spring Data JPA repository
- Jakarta Bean Validation on request DTOs
- Custom domain exceptions and global error handling
- `@ConfigurationProperties` with dev and test profiles
- Unit, web-layer (`@WebMvcTest`), repository, service integration, and HTTP
  integration tests with Testcontainers
- Actuator health and info endpoints (limited exposure)
- README, curl/Postman samples, and self-review deliverables

### Out of scope

- Authentication, authorization, rate limiting, or multi-tenancy
- `/api/v1` versioning (exercise contract uses `/api/products`)
- Production deployment, CI pipelines (initial agentic setup)
- Logging sensitive data (passwords, tokens, full request bodies)

## Architecture

```text
controller → service → repository (Spring Data JPA) → PostgreSQL
     ↓           ↓
   dto        entity + mapper
exception ← config (CatalogProperties)
Flyway → schema
```

Package layout under `com.codewalnut.productcatalog`:

| Package | Responsibility |
| --- | --- |
| `controller` | HTTP mapping, status codes, headers, `@Valid` |
| `service` | Business rules, DTO mapping orchestration, transactions |
| `repository` | Spring Data JPA + Specifications |
| `entity` | JPA persistence model (`ProductEntity`) |
| `dto` | Request, response, and error payloads |
| `exception` | Domain exceptions and `@RestControllerAdvice` |
| `config` | `@ConfigurationProperties` and profile wiring |
| `mapper` | Entity ↔ DTO mapping |

## Product data model

| Field | Type | Rules |
| --- | --- | --- |
| id | UUID | Server-generated; immutable |
| sku | String | Required; unique (case-insensitive) |
| name | String | Required |
| category | String | Required |
| price | BigDecimal | Required; > 0; max 17 integer + 2 fraction digits |
| stockQuantity | int | >= 0 |
| active | boolean | Stored and returned as provided |
| version | long | Optimistic lock; returned on GET; optional on PUT/PATCH stock |
| createdAt / updatedAt | Instant | Server-managed timestamps |

## Open questions (resolved)

1. **Product limit exception:** HTTP 409 Conflict when maximum products is reached. **Yes.**
2. **Default category:** Configured in `catalog.default-category`; category remains
   required on requests. **No API defaulting.**
3. **List contract:** Week 6 uses a **page envelope** for `GET /api/products`
   (breaking change from Week 5 array). Documented in REQ-013 / AC-011.
4. **Catalog max race:** `count()` guard is best-effort under concurrent creates
   (default isolation). Documented limitation; no SERIALIZABLE.
