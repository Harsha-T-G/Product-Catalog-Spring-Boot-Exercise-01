# Product Catalog Product Specification

**Status:** Draft — Exercises 1–3 implemented on branch `exercise-3-validation`; pending human review  
**Stack:** Java 21, Spring Boot 3.4.x, Maven, JUnit 5, Mockito  
**Exercise source:** Week 5 Spring Boot Fundamentals (`harsha_week5_spring_boot_fundamentals_exercises.txt`)

## Assumptions

1. Base package is `com.codewalnut.productcatalog`; Maven coordinates are
   `com.codewalnut:product-catalog`.
2. All six exercises build incrementally in this single repository on branch
   checkpoints (`exercise-1-setup` through `exercise-6-tests`).
3. Data is stored in memory only. No database, Spring Data JPA, or file
   persistence.
4. Lombok is not used. Constructor injection only; no field `@Autowired`.
5. Controllers handle HTTP only. Business logic lives in the service layer.
6. REST boundaries use request/response DTOs; internal `Product` model is never
   returned directly.
7. Product id is a UUID generated by the application on create and never changes
   on update.
8. SKU comparison is case-insensitive for uniqueness checks.
9. Price uses `BigDecimal` and must be greater than zero. Stock quantity is zero
   or greater.
10. Inactive products (`active=false`) are stored and retrieved normally but
    excluded from low-stock queries.
11. Secrets and environment-specific overrides use environment variables, not
    committed configuration files.
12. Java 21 is the release target.

## Objective

Build a Product Catalog REST API that demonstrates Spring Boot fundamentals:
project setup, layered architecture, validation, centralized error handling,
type-safe configuration with profiles, and layered automated testing including
Actuator health.

## Scope

### In scope

- REST API for product CRUD and low-stock listing
- In-memory repository with thread-safe storage
- Jakarta Bean Validation on request DTOs
- Custom domain exceptions and global error handling
- `@ConfigurationProperties` with dev and test profiles
- Unit, web-layer, and integration tests
- Actuator health and info endpoints (limited exposure)
- README, curl/Postman samples, and self-review deliverables

### Out of scope

- Database, JPA, or external persistence
- Lombok, authentication, authorization, or multi-tenancy
- Pagination, search indexing, or caching
- Production deployment, CI pipelines (initial agentic setup)
- Logging sensitive data (passwords, tokens, full request bodies)

## Architecture

```text
controller → service → repository
     ↓           ↓
   dto        model
exception ← config (CatalogProperties)
```

Package layout under `com.codewalnut.productcatalog`:

| Package | Responsibility |
| --- | --- |
| `controller` | HTTP mapping, status codes, headers, `@Valid` |
| `service` | Business rules, DTO mapping orchestration |
| `repository` | In-memory persistence interface + implementation |
| `model` | Internal product entity |
| `dto` | Request, response, and error payloads |
| `exception` | Domain exceptions and `@RestControllerAdvice` |
| `config` | `@ConfigurationProperties` and profile wiring |

## Product data model

| Field | Type | Rules |
| --- | --- | --- |
| id | UUID | Server-generated; immutable |
| sku | String | Required; unique (case-insensitive) |
| name | String | Required |
| category | String | Required |
| price | BigDecimal | Required; > 0 |
| stockQuantity | int | >= 0 |
| active | boolean | Stored and returned as provided |
